# 开发流程规范

> 适用项目：NC 刀路查看器（NCodeViewer）
> 作用：**严格遵循**的开发 / 测试 / 打包 / 发布流程。任何流程本身的变更，也须同步维护到本文档。

---

## 1. 核心原则

1. **TDD 先行**：先写（或更新）测试 → 让测试 FAIL（红）→ 实现使其 PASS（绿）→ 再打包/发布。
2. **每次改动都有测试**：任何代码/界面改动都应有对应测试用例保护，防止回归。
3. **绿灯后才打包**：`pytest` 全绿（green）之前，不执行打包、不发布 EXE。
4. **最小改动**：只改任务所需，不顺手重构无关代码。
5. **变更留痕**：所有改动同步写入 `CHANGELOG.md`。

---

## 2. 环境要求

| 项 | 要求 |
| --- | --- |
| Python | ≥ 3.8：**必须自带 Tkinter**（验证 3.8 / 3.11 / 3.14）；**Win7 目标构建必须用 conda 的 Python 3.8**（3.9+ 不支持 Win7） |
| 运行时依赖 | 仅标准库 |
| 测试依赖 | `pytest`（3.8 环境需 `<9`） |
| 打包依赖 | `PyInstaller`（脚本会自动安装；Win7 构建须为 **5.x**，bat 自动固定 5.13.2） |

> 排查：`import tkinter` 报错 → 当前解释器未捆绑 Tkinter，改用 conda `python38` 环境或 `py -3.11` / `py -3.14`。

---

## 3. 目录与模块约定

```
src/nc_viewer/
├── parser.py      # NC/G 代码解析（纯计算，不依赖 Tkinter）
├── geometry.py    # 配色 / 圆弧离散 / 四元数旋转 / 投影（纯计算）
├── viewer.py      # Tkinter 主窗口（可依赖上述模块）
├── __main__.py    # python -m nc_viewer 入口
└── __init__.py    # 包接口（NCViewer 延迟导入）

tests/             # pytest 用例
docs/              # 技术手册、开发流程
CHANGELOG.md       # 更改记录
launcher.py        # PyInstaller 打包入口
build_exe.bat      # 打包脚本
```

- **纯计算与 UI 分离**：`parser`、`geometry` 不得 `import` Tkinter，保证可独立单测。
- 新增逻辑优先放入对应模块；若属纯计算，写进 `geometry` / `parser`。

## 4. 开发 / 测试流程

### 4.1 标准步骤（每次改动）

```bash
# 1) 写/更新测试（RED）
#    在 tests/ 下新增或修改对应测试用例

# 2) 运行测试，确认针对新功能是失败的（可选，验证测试有效）
python -m pytest -q

# 3) 实现功能（GREEN）
#    修改 src/nc_viewer/ 下对应模块

# 4) 全量回归，必须全部通过
python -m pytest -q

# 5) 更新 CHANGELOG.md
```

### 4.2 测试命令

```bash
# 全量测试
python -m pytest -q

# 指定文件
python -m pytest tests/test_parser.py -q

# 指定用例（-k 关键字）
python -m pytest -k "arc" -q
```

> `pyproject.toml` 已配置 `testpaths=["tests"]`、`pythonpath=["src"]`，无需安装即可跑测试。
> Win7 目标构建前，建议同时用 conda python38 跑一遍回归：`<conda38-python> -m pytest -q`（本机路径见本地版文档）

### 4.3 测试覆盖要求

- 解析逻辑（`parser`）：G0/G1/G2/G3、F 模态、平面、绝对/增量、N 行号、位置跟踪、注释容错、真实样例。
- 几何逻辑（`geometry`）：轨道旋转方向、四元数规范性、旋转中心不动、圆弧离散。
- 界面结构（`viewer`）：试 UI 改动需附回归测试（如按钮去重）；无显示环境（CI）用 `pytest.skip` 跳过。

## 5. 打包流程

### 5.1 前置条件

- [ ] 全量测试 green
- [ ] EXE 冒烟测试通过（见 5.3）

### 5.2 执行打包

```bash
# 方式一（推荐）：运行打包脚本 build_exe.bat
# 或 .\build_exe.bat
```

`build_exe.bat` 自动探测构建解释器，顺序为：
1. 环境变量 `NCVIEWER_PY`（python.exe 完整路径）显式指定
2. conda `python38` 环境（**Win7 目标构建优先**）
3. `py -3.11` / `py -3.14`（Win10/11 构建）

用 conda python38 构建时：自动固定 PyInstaller 5.13.2（6.10+ 的 bootloader 不支持 Win7），并把 UCRT 运行时（`ucrtbase.dll` + `api-ms-win-crt-*.dll`）打包进 EXE，裸装 Win7 无需 KB2999226 补丁。

```bash
# 方式二：手动 PyInstaller 命令（Win7 目标示例，用 conda python38）
<conda38-python> -m PyInstaller --onefile --windowed --name NCViewer --paths src --add-binary "<conda38-root>\ucrtbase.dll;." --clean launcher.py
```

输出：`dist\NCViewer.exe`（单文件、无控制台）。`<conda38-python>` / `<conda38-root>` 为本机路径占位符，实际路径见本地版文档。

### 5.3 冒烟测试（打包后必做）

```bash
# 启动 EXE，确认进程存活（非立即崩溃）
$p = Start-Process "dist\NCViewer.exe" -PassThru
Start-Sleep -Seconds 4
if ($p.HasExited) { "FAIL code=$($p.ExitCode)" } else { "OK"; Stop-Process $p.Id -Force }
```

### 5.4 打包注意事项

- 打包入口必须是 `launcher.py`（`__main__.py` 使用相对导入，不能直接作为 PyInstaller 入口）。
- `build_exe.bat` 需保持 **CRLF 换行**（bat 文件用 LF 会解析丢字符）。
- 若改动涉及新数据文件，需通过 `--add-data` 一并打包。
- **Win7 目标**：构建解释器必须是 Python 3.8（conda `python38`），PyInstaller 必须是 **5.x**（6.10+ 的 bootloader 不再支持 Win7）；打包日志应出现「内置 UCRT 运行时」。
- **Win7 实测**：本机（Win10/11）冒烟通过 ≠ Win7 可运行，发布前必须在真实 Win7 机器上打开样例文件验证渲染/旋转/定位。

## 6. 变更记录流程

- 每次改动在 `CHANGELOG.md` 顶部追加一行，格式：
  `- <类型> <一句话说明>`
- 类型：`新增 / 修改 / 修复 / 移除 / 文档 / 打包 / 测试`
- 改动较大或对外发布时，新建版本条目 `[x.y.z] - YYYY-MM-DD`。

## 7. 发布检查清单

- [ ] 全量测试 green

- [ ] `CHANGELOG.md` 已更新
- [ ] EXE 重新打包
- [ ] EXE 冒烟测试通过

若开发/测试/打包流程本身发生变化（如换打包工具、改测试框架、新增 CI 等），**必须同步更新本文档**，并在 `CHANGELOG.md` 记录该流程变更。
