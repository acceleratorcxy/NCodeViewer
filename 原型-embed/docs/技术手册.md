# NC 刀路查看器 Qt 离屏渲染实验版 技术手册

> 版本：0.1.0 ｜ 适用源码包：`src/nc_viewer`（原型-embed）｜ 运行环境：Windows（10/11，Win7 目标见注意事项） / Python 3.8+（需自带 Tkinter）
> **相关文档**：开发/测试/打包流程见 [开发流程.md](开发流程.md)；历次改动见 [CHANGELOG.md](../CHANGELOG.md)。
> **本实验版定位**：验证「Qt OpenGL 渲染嵌入 Tk 界面」方案——界面与交互完全保持主程序 Tk 实现，仅画布刀路渲染替换为 Qt 离屏 OpenGL，目标在完整刀路（不抽稀）下实现 60fps 交互。

## 1. 项目概述

NC 刀路查看器是一款桌面工具，用于可视化查看 NC/G 代码（如海德汉、西门子等系统的 `.MPF` 文件）的加工刀路。它把逐行文本解析为 3D 刀路段，并按进给 `F` 值着色，辅助程序员直观检查刀具轨迹、定位到指定代码行的刀具位置。

**与主程序（纯 Tkinter 渲染）的区别**：仅画布渲染层不同——本实验版以 Qt 离屏 OpenGL（`QOffscreenSurface + FBO`）绘制刀路与全部画布标记，读回图像由 Tk canvas 显示；**不产生任何独立 Qt 窗口**，界面外观与操作与主程序完全一致。

### 1.1 核心能力

| 能力 | 说明 |
| --- | --- |
| NC 解析 | 处理 G0/G1/G2/G3、F 模态、G17/G18/G19 平面、G90/G91、I/J/K 圆心、N 行号、`;`/`()` 注释（与主程序一致） |
| F 值配色 | 不同 F 进给以蛇形色相生成高区分度颜色；G0 快移为灰色；图例同步显示（与主程序一致） |
| 圆弧离散 | 同时按「最大圆心角 0.1 rad」和「最大段长 4mm」双因素取段数，小圆弧不失真（与主程序一致） |
| 按行定位 | 输入行号或 `N6` 形式，标出刀具实际位置（十字 + 当前段高亮 + 方向箭头，由 Qt overlay 绘制） |
| 多文件 / 搜索 / 统计 / F 曲线 | 与主程序一致（F 曲线仍为 Tk 二级窗口） |
| 逐行运行 | 播放控制条：连续播放/暂停、单步、复位、直达行、演示到行；**移动级渐进**——刀路按移动逐步增长（走到哪显示到哪） |
| 按段浏览 | 抬刀平面可编辑 + 段导航 + 仅显示当前段（段内播放，钳制在段内停止） |
| 视图交互 | 四元数轨道球旋转（中键）、平移（左键）、缩放（滚轮）、三视图 XY/XZ/YZ、一键适配 |
| **Qt 离屏渲染** | 全量刀路 VBO（合并折线、不抽稀），旋转/缩放/平移只更新 MVP 重渲染；overlay 由 GL 立即模式绘制；FBO 离屏渲染读回 Tk 显示 |

### 1.2 设计原则

- **纯计算与 UI 分离**：解析（`parser`）、几何数学（`geometry`）、刀具（`tool`）不依赖 Tkinter/PyQt5，可独立单元测试；`viewer` 只负责界面、交互与状态。
- **渲染分层**：`qt_offscreen` 只做 GPU 渲染（VBO 构建、MVP、overlay），与 `viewer` 经 `set_result / set_tool / render` 接口通信；OpenGL 不可用时（`_qt_ready=False`）自动回退主程序 Tk 渲染。
- **渲染性能（本版核心）**：
  - **全量 VBO 一次上传**：加载/段过滤/G0/刀具变化（data 版本 key）才重建；合并折线（同色连续、共享端点），**不抽稀、不断线**；
  - **交互零重建**：旋转/缩放/平移只更新 MVP uniform → 重渲染一帧（离屏 GL，2.5 万段完整刀路实测流畅）；
  - **逐移动裁剪播放**：播放/单步按移动逐步增长（`_trace_drawn` + `_move_seg_map`），渲染 `glDrawArrays` 裁剪到移动边界；
  - **PhotoImage 复用**：播放每 tick 用 `paste` 更新像素，Tk 图片对象不累积。
- **TDD**：核心解析、几何、离屏渲染（VBO/seg_map 粒度）均有测试保护。

## 4. 界面与操作

界面布局、三栏宽度自适应、深色主题、文件列表双区、统计/位置/刀具侧栏、播放控制条、目标行语义、当前行居中、加工时间进度、F 曲线、按段浏览、定位与搜索等**与主程序完全一致**，此处不再展开，仅列与 Qt 离屏渲染相关的变化点：

- **画布刀路**：由离屏 OpenGL 渲染为整幅图像显示在画布上；平移/旋转/缩放/适配均重渲染，**无 Tk 折线图元**。
- **画布标记**（十字虚线、当前段高亮、加工方向箭头、当前点、XYZ 轴、3D 刀具模型）：由 GL 立即模式 overlay 绘制，像素尺寸固定（**镖形方向箭头 28px**、点 7px、十字暗化不刺眼）。
- **XYZ 方向指示器**：固定画布**左下角**（红 X/绿 Y/青 Z，轴端实心箭头 + QPainter 叠加的加粗文字标识），随旋转变化、任何视角始终可见；**世界原点 (0,0,0) 另绘一组更大的坐标系**（轴长随缩放、最小 60px，箭头 10px、文字 12px），刀路定位点附近始终可见，原点处有白色小点标记。
- **3D 刀具模型**：**旋转体外表面网格填充**（轮廓曲线绕轴 24 段生成表面三角形，整个圆柱面/球头/刀柄上色，实体 #8f8f99 + 顶面圆盘 #a8a8b2 + 剪影描边）——侧面/斜视角显示**完整外表面实体**（旧版填过轴心剪影薄片，斜视角投影成"中间一片"、外表面透明）；填充色亮于背景避免假透明，无线框噪音（无经线/截面圆线框）；俯视视角刀具侧面几何不可见，显示顶面圆 + 轮廓线属正常。
- **轨迹渐进（移动级）**：播放/演示/单步/直达从空白画布起，刀路按**移动**逐步增长（"走到哪显示到哪"），同色段合并显示；后退整段重绘；播放中旋转/缩放/平移保持轨迹模式。**刀具钉在刀路最后移动的终点**（与已画刀路同步，不落后）；播放行号推进**修正到有移动的行**（头注释/空行不产生执行位置）；前导起始进给（从原点出发的对刀段）不显示。**演示到行与播放同速**（每帧合并推进 batch 行、同一速度档，刀路绘制速度一致）。
- **Tk 回退渲染**：OpenGL 不可用时回退主程序 Tk 渲染（含轴/当前行标记/3D 刀具完整 Tk 实现）；Qt 接管后 Tk 标记函数 no-op、render() 统一清理 fallback 残留图元（axes/axescorner/path/cur/curseg/toolmodel），无双轨混叠。
- **合并跳行**：仍为行级推进语义（一次推进 N 行），渲染回推到目标行最后移动。
- **段模式播放**：钳制在勾选段内，到段尾自动停止。
- **画布尺寸变化**：按新尺寸重建 PhotoImage 重渲染（复用图片项，不 delete/create）。

### 5.3 Qt 离屏渲染链路（核心）

```
加载 NC ──parse_nc──> ParseResult ──set_result(result, palette, seg_filter, show_g0)
                                   └─> 合并折线 VBO 上传 (GL_LINES, 全量不抽稀)
                                        + _move_seg_map[i] = 移动 i 完成后的累计段数

交互 (旋转/缩放/平移/播放/拾取)
   └─> viewer 更新 quat/scale/offset/_trace_drawn/current_line
        └─> _qt_render() ──> render(quat, scale, offset, W, H, trace_drawn, ...)
             ├─ 刀路: 更新 MVP uniform → glDrawArrays 裁剪到 trace_drawn 段数
             ├─ overlay: GL 立即模式 (XYZ轴/当前行高亮/箭头/十字线/3D刀具)
             ├─ FBO.toImage() → convertToFormat(RGB888)
             ├─ PIL frombuffer (按 bytesPerLine stride, 防 45° 斜线)
             └─ ImageTk.PhotoImage (复用 paste) → canvas create_image/itemconfig
```

### 5.4 关键状态与语义

- **`_qt_ready`**：`after(150)` 初始化离屏渲染器后为 True；False 时走 Tk 回退渲染。
- **data 版本 key**：`(id(result), _seg_filter, show_g0, id(tool), show_tool)` —— 变化才重建 VBO，否则只渲染。
- **`_trace_drawn`**：轨迹模式下已执行移动数（渲染裁剪边界），前导跳过从 `_trace_base()` 起。
- **`_move_seg_map`**：`seg_map[i]` = 移动 i 完成后的真实累计段数（已落库 + 当前折线段数），播放渐进按它精确裁剪；**合并进同色折线的移动必须实时计入**（否则颜色段内部不显示）。
- **PhotoImage 复用**：画布尺寸不变时 `paste` 更新像素；变化时重建。

## 6. 核心算法说明

解析（6.1）、圆弧离散（6.2）、轨道球旋转（6.3）与主程序一致，此处略。本版特有：

### 6.1 合并折线 VBO（`qt_offscreen.set_result`）

- 逐移动取 3D 离散点（`move_points_3d`），同色（F 值相同）且共享端点时并入当前折线（`poly.extend(pts[1:])`），否则 flush 落库为行顶点对；**段数不减（不抽稀）**。
- 落库格式：每段 2 顶点（`GL_LINES`），顶点交错排列（起点/终点成对），VBO 顶点数 = 段数 × 2。
- `_move_seg_map[i] = flushed + len(poly) - 1`：flushed 为已落库段数，`len(poly)-1` 为当前折线段数；移动 i 完成后的真实累计段数逐移动精确（**修复"一段颜色执行完才显示"**）。

### 6.2 播放渐进裁剪（`render` 的 `trace_drawn`）

- 播放每 tick 维护 `_trace_drawn`（行级推进语义 + 渲染回推目标行最后移动），渲染时 `segs = _move_seg_map[trace_drawn-1]`，`glDrawArrays(GL_LINES, 0, segs*2)` 只画到该移动边界。
- 全量渲染（无轨迹）时 `trace_drawn=None` 画完整 VBO。

### 6.3 交互渲染（零 VBO 重建）

- 旋转/平移/缩放只改 `quat/scale/offset` → 重渲染一帧；MVP 由四元数行优先矩阵构造（row 3 全 0，z 不裁剪）。
- 圆弧抽稀/合并刷新仅存在于主程序 Tk 渲染路径，**本版不抽稀**（GPU 渲染足够快）。

### 6.4 读回与显示（`viewer._qt_render`）

- `FBO.toImage()` 为 ARGB32（BGRA 4 字节/像素），`convertToFormat(RGB888)` 后按 `bytesPerLine()` stride 用 `PIL Image.frombuffer("RGB", (W,H), data, "raw", "RGB", bpl, 0)` 逐行取（**不按 stride 会错位成 45° 斜线**）。
- PhotoImage 复用（`paste`），canvas 图片项复用（`itemconfig`），画布尺寸变化时重建。

## 8. 常见问题（FAQ）

**Q：画面没有任何刀路（黑底）？**
A：确认 OpenGL 可用（`_qt_ready` 为 True）；若为 False 已回退 Tk 渲染。首次启动 150ms 内尚未初始化属正常。

**Q：画布出现 45° 斜线/错位？**
A：读回 QImage 必须按 `bytesPerLine()` stride 逐行取；确认 `_qt_render` 使用 `Image.frombuffer(..., "raw", "RGB", bpl, 0)`。

**Q：播放越用越卡？**
A：每帧必须复用 PhotoImage（`paste` 更新）；若每帧新建 Tk 图片对象会累积导致卡顿。

**Q：播放时刀路"一段颜色执行完才显示"？**
A：`_move_seg_map` 必须逐移动实时计段（含合并折线）；确认未回退旧实现（只计 flush 边界）。

**Q：切换"显示刀具"开关不生效？**
A：data 版本 key 必须含 `show_tool`；确认未漏加。

**Q：能在 Windows 7 上运行吗？**
A：可以（64 位 Win7）。须用 conda 的 Python 3.8 构建（PyInstaller 5.x + UCRT），且运行时依赖用支持 Win7 的版本（PyQt5 5.15.x、numpy<2、Pillow<11）。

**Q：其他问题（解析/定位/段/播放语义）？**
A：界面与交互逻辑与主程序一致，见主程序技术手册对应章节。

## 9. 扩展指南

- **调整渲染**：`qt_offscreen` 的 VERT_SRC/FRAG_SRC（着色）、`_mvp`（投影）、`_draw_overlay`（标记绘制）。
- **新增画布标记**：在 `qt_offscreen._draw_overlay` 用立即模式绘制，注意固定像素尺寸（用 NDC 换算）。
- **调整圆弧精度/配色/刀具**：同主程序（`geometry.arc_points` / `build_palette` / `tool`）。
- **打包与 EXE**：运行 `build_exe.bat`（详见 [开发流程.md](开发流程.md) 第 5 节），产物 `dist\NCViewer.exe`。

## 10. 注意事项（开发 / 运行 / 使用 / 打包）

> 本章汇总本项目所有**必须注意**的事项，改动与使用前请先通读。

### 10.1 运行环境
- 必须使用**自带 Tkinter** 的 Python（验证 3.8 / 3.11）；运行时还需 PyQt5/numpy/Pillow。
- **Win7 目标**：构建解释器必须是 conda 的 Python 3.8；依赖版本须支持 Win7（PyQt5 5.15.x、numpy<2、Pillow<11）。
- 命令行仅支持加载**单个**文件；多文件请用界面「打开文件…」多选。

### 10.2 开发约束
- **纯计算与 UI 分离**：`parser`、`geometry`、`tool` 不得 `import` Tkinter / PyQt5；`qt_offscreen` 不 `import` Tkinter。
- **TDD**：先写测试 → 实现 → 全绿（green）→ 再打包；每次改动都应有对应测试。
- **渲染质量优先**：刀路显示不得抽稀、不得断线；任何降低刀路显示质量的方案直接否决。
- **Qt 渲染专属约束**（详见开发流程 4.4）：
  - QApplication 创建后须经事件循环小段间隔再建离屏 surface（否则访问违规崩溃）；
  - PhotoImage 必须复用（`paste`），禁止每帧新建；
  - `_move_seg_map` 逐移动实时计段（含合并折线）；
  - data 版本 key 必须覆盖所有几何输入（含 `show_tool`）；
  - Qt 接管渲染后 Tk 侧不再产生刀路/标记图元，`render()` Qt 分支清理回退残留。

### 10.3 运行/使用注意
- **性能**：VBO 全量上传一次（不抽稀）；交互只重渲染一帧；播放渐进按移动裁剪。
- **旋转手感**：旋转中心取点击处 12px 内最近刀路点，否则锚定点击处反投影点（同主程序）。

### 10.4 打包注意
- 打包入口必须是**`launcher.py`**（`__main__.py` 用相对导入，不能直接作为 PyInstaller 入口）。
- `build_exe.bat` 需保持 **CRLF 换行**（LF 会导致 cmd 解析丢首字符）。
- 新增数据/资源文件需通过 `--add-data` 一并打包；PyQt5 DLL 缺失时用 `--collect-all PyQt5`。
- **Win7 目标**：必须用 conda `python38`（Python 3.8）构建，且 PyInstaller 必须为 **5.x**（6.10+ 的 bootloader 不支持 Win7）。
- **Win7 裸机运行**：conda 构建时 bat 自动把 UCRT 打包进 EXE，目标 Win7 无需 KB2999226 补丁。
- **发布前**：全量测试 green + EXE 冒烟测试通过（Win7 目标还须在真实 Win7 机器上实测）。
